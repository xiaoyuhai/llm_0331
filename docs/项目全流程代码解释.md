## 1. 项目总览:这条教学线在教什么

整个仓库是一条 **"从零搭 Transformer → SFT 让模型会对话 → 推理验证 → DPO 让模型答案更受人喜欢"** 的 LLM 训练全流程教学。

```
01_Qwen3.py          从零实现 Qwen3 的模型结构(只懂结构,还不会对话)
      ↓  (拿到一个能说话但胡言乱语的模型)
02_sft_demo.py       SFT 监督微调,教会模型"该怎么回答"(复读标准答案)
      ↓  (模型变对话模型)
03_model_generate.py 加载微调后的模型,跑自回归生成验证效果
      ↓  (验证完发现模型会说话但答案可能不好)
04_dpo_demo.py       DPO 直接偏好优化,让模型学会"哪个回答更好"
      ↓  (模型答案更对齐人类偏好)
```

| 文件 | 角色 | 是否需要权重 |
|---|---|---|
| `01_Qwen3.py` | 手写 Transformer 实现 | 需要 `model/Qwen3-0.6B/` 下的真实权重才能生成正常文本 |
| `02_sft_demo.py` | 用 HF `AutoModelForCausalLM` 做 SFT | 需要 `model/Qwen3-0.6B-Base/` |
| `03_model_generate.py` | 推理脚本 | 用 `finetuned/02_sft_demo` 下的微调产物 |
| `04_dpo_demo.py` | DPO | 用 SFT 输出 + UltraFeedback 偏好数据 |
| `llm_config.py` | 全局路径常量 | - |
| `device_utils.py` | 设备选择工具 | - |

## 3. `01_Qwen3.py` — 从零实现 Qwen3-0.6B

> **核心目标**:不调用 HF 的 `Qwen3ForCausalLM`,只用 `torch.nn` 自己搭出完整的 Qwen3 架构,并能加载 HF 权重跑通生成。

### 3.1 模型配置 `QWEN_CONFIG_06_B`(行 10-25)

```python
QWEN_CONFIG_06_B = {
    "vocab_size": 151936,              # 词表大,Qwen3 词表约 15 万
    "max_position_embeddings": 40_960, # 支持的最大上下文长度
    "hidden_size": 1024,               # 隐藏维度(每层 token 向量都是 1024 维)
    "intermediate_size": 3072,         # FFN 中间层维度(比 hidden 大 3 倍)
    "hidden_act": "silu",              # SwiGLU 内部用 silu 激活
    "num_hidden_layers": 28,           # Transformer Block 个数(0.6B 是 28 层)
    "num_attention_heads": 16,          # Query 头数(Q 头多)
    "num_key_value_heads": 8,          # KV 头数(K/V 头少,与 Q 头共享 → GQA)
    "head_dim": 128,                   # 每个头 128 维
    "qk_norm": True,                   # Q/K 做 RMSNorm(防止方差爆炸)
    "rope_theta": 1_000_000.0,         # RoPE base frequency,1e6 是长上下文常用值
    "rms_norm_eps": 1e-6,              # RMSNorm 里的 epsilon
    "tie_word_embeddings": True,       # 输入 embedding 和输出 lm_head 共享权重(省参数)
    "torch_dtype": torch.bfloat16,     # 全程 bf16
}
```

每个参数的作用后面在对应类里会再用到,这里先记住"维度 1024 / 28 层 / 16Q头+8KV头"。

### 3.2 类结构

```
Qwen3Model            ← 最外层模型
 ├─ tok_emb           ← token embedding
 ├─ trf_blocks        ← 28 个 TransformerBlock
 │    └─ (norm1, attention, norm2, FeedForward, 残差)
 ├─ final_norm        ← 最后一层 RMSNorm
 └─ out_head          ← lm_head(与 tok_emb 权重共享)

TransformerBlock
 ├─ norm1            ← Pre-Norm
 ├─ att              ← GroupedQueryAttention
 ├─ norm2
 └─ ff               ← SwiGLU FeedForward

GroupedQueryAttention
 ├─ q_proj / k_proj / v_proj / o_proj
 ├─ q_norm / k_norm  ← Q/K 的 RMSNorm
 └─ apply_rope       (函数,不是模块)

FeedForward
 ├─ gate_proj + silu
 ├─ up_proj
 └─ down_proj         (SwiGLU 结构)

RMSNorm                ← 自定义归一化
```

### 3.3 `Qwen3Model.__init__`(行 30-64)

```python
self.tok_emb = nn.Embedding(cfg["vocab_size"], cfg["hidden_size"], dtype=cfg["torch_dtype"])
self.trf_blocks = nn.ModuleList([TransformerBlock(cfg) for _ in range(28)])
self.final_norm = RMSNorm(cfg["hidden_size"], eps=cfg["rms_norm_eps"])
self.out_head = nn.Linear(cfg["hidden_size"], cfg["vocab_size"], bias=False)
if cfg["tie_word_embeddings"]:
    self.out_head.weight = self.tok_emb.weight   # 共享权重
```

- `nn.ModuleList`:比普通 list 多了**自动注册子模块参数**的作用,`model.parameters()` 能找到它们。
- **权重共享**:输入 embedding(`vocab_size × hidden_size`)和输出 lm_head(`hidden_size × vocab_size`)形状互为转置,共享后省约 150M 参数(对 0.6B 模型占比不小)。

后面的 `register_buffer("cos", cos)`:把预计算好的 RoPE 的 cos/sin 注册进模块。`persistent=False` 表示序列化模型时**不存盘**(下次用可以重新算)。
`self.current_pos = 0`:用于 KV cache 追踪当前解码到的位置索引。

### 3.4 `Qwen3Model.forward`(行 66-113) — prefill vs decode 的区别

这是整个文件最核心的入口,看懂这里就懂了 KV cache 工作方式。

```python
def forward(self, in_idx, cache=None):
    tok_embeds = self.tok_emb(in_idx)         # [B, seq_len] → [B, seq_len, hidden]
    x = tok_embeds
    num_tokens = x.shape[1]
    if cache is not None and len(cache) > 0:    # decode 阶段(已经有历史 cache)
        pos_start = self.current_pos
        pos_end = pos_start + num_tokens       # decode 时 num_tokens=1
        self.current_pos = pos_end
        mask = torch.triu(torch.ones(pos_end, pos_end, ...), diagonal=1)
                 [pos_start:pos_end, :pos_end]   # 只切当前 token 那一行
    else:                                       # prefill 阶段
        pos_start = 0
        mask = torch.triu(torch.ones(num_tokens, num_tokens, ...), diagonal=1)
        self.current_pos = num_tokens
    mask = mask.unsqueeze(0).unsqueeze(0)        # [1, 1, query_len, key_len]

    for i, block in enumerate(self.trf_blocks):
        blk_cache = cache.get(i) if cache else None
        x, new_blk_cache = block(x, mask, self.cos, self.sin, start_pos=pos_start, cache=blk_cache)
        if cache is not None:
            cache[i] = new_blk_cache            # 每层 cache 写回字典

    x = self.final_norm(x)
    logits = self.out_head(x.to(self.cfg["torch_dtype"]))  # [B, seq, vocab]
    return logits
```

关键设计:
1. **两阶段共享一个 forward**:用 `cache` 参数区分。
   - prefill(`cache={}` 或 `None`):一次喂完整 prompt,算 seq×seq 的全因果 mask。
   - decode(`cache` 非空):每次只喂 1 个 token,只切 mask 的那一行,速度大幅提升。
2. `self.current_pos` 是模型级位置指针:prefill 后等于 prompt 长度;每 decode 一次 +1。
3. `mask` 形状 `[1,1,q_len,k_len]`:`unsqueeze(0).unsqueeze(0)` 是为了广播到每个 batch 每个头。
4. `cache` 是个字典 `layer_idx → (K, V)`,每层独立缓存。

### 3.5 `TransformerBlock.forward`(行 135-151) — Pre-Norm + 残差

```python
shortcut = x
x = self.norm1(x)                  # Pre-Norm:先norm再attention
x, next_cache = self.att(x, mask, cos, sin, start_pos=start_pos, cache=cache)
x = x + shortcut                  # 残差连接

shortcut = x
x = self.norm2(x)
x = self.ff(x)
x = x + shortcut
return x, next_cache
```

- **Pre-Norm**(先 norm 再进 attention/FFN)比 Post-Norm 训练稳定,Llama 系都这么做。
- 两次残差连接:一次 attention 后,一次 FFN 后。残差让梯度可以一路短接回去,28 层才训得动。

### 3.6 `GroupedQueryAttention`(行 167-264) — 全文件难点

#### 3.6.1 `__init__` 参数

```python
self.q_proj = nn.Linear(d_in, num_heads * head_dim, bias=False)         # 1024 → 2048
self.k_proj = nn.Linear(d_in, num_kv_groups * head_dim, bias=False)     # 1024 → 1024
self.v_proj = nn.Linear(d_in, num_kv_groups * head_dim, bias=False)     # 1024 → 1024
self.o_proj = nn.Linear(num_heads * head_dim, d_in, bias=False)         # 2048 → 1024
self.group_size = num_heads // num_kv_groups                            # 16/8 = 2
if qk_norm:
    self.q_norm = RMSNorm(head_dim); self.k_norm = RMSNorm(head_dim)
```

- **GQA 关键**:Q 头 16 个,K/V 头只有 8 个,每 2 个 Q 头共享 1 个 KV 头,省一半 KV cache。
- 业务上为什么 GQA:KV cache 在长上下文里占显存大头,GQA 把 KV 量减半,推理更便宜。
- `q_norm / k_norm`:对每个头的 128 维向量做 RMSNorm,稳定注意力分数(防方差爆炸导致 softmax 饱和)。

#### 3.6.2 `forward` 前向(行 206-264)

```python
# 投影出 Q/K/V
queries = self.q_proj(x)   # [B, seq, 2048]
keys = self.k_proj(x)      # [B, seq, 1024]
values = self.v_proj(x)

# reshape 成多头
queries = queries.view(B, seq, 16, 128).transpose(1, 2)   # [B, 16, seq, 128]
keys_new = keys.view(B, seq, 8, 128).transpose(1, 2)     # [B, 8, seq, 128]
values_new = values.view(B, seq, 8, 128).transpose(1, 2)

# Q/K norm
queries = self.q_norm(queries)
keys_new = self.k_norm(keys_new)

# 应用 RoPE(按位置旋转)
queries = apply_rope(queries, cos, sin, offset=start_pos)
keys_new = apply_rope(keys_new, cos, sin, offset=start_pos)

# KV cache 拼接(decode 时历史+当前)
if cache is not None:
    prev_k, prev_v = cache
    keys = torch.cat([prev_k, keys_new], dim=2)
    values = torch.cat([prev_v, values_new], dim=2)
else:
    keys, values = keys_new, values_new
next_cache = (keys, values)   # 本层新 cache

# ⭐ GQA 复制:把 8 个 KV 头复制成 16 个,跟 Q 头一对一
keys = keys.repeat_interleave(self.group_size, dim=1)
values = values.repeat_interleave(self.group_size, dim=1)

# 标准注意力
attn_scores = queries @ keys.transpose(2, 3)            # [B, 16, seq, seq]
attn_scores = attn_scores.masked_fill(mask, -torch.inf)  # 因果 mask
attn_weights = torch.softmax(attn_scores / sqrt(head_dim), dim=-1)
context = (attn_weights @ values).transpose(1, 2).reshape(B, seq, 2048)

return self.o_proj(context), next_cache   # 再投影回 1024
```

`repeat_interleave(group_size=2, dim=1)` 的含义:
- 原来 keys 形状 `[B, 8, seq, 128]`
- 沿头维度复制成 `[B, 16, seq, 128]`:第 0 个头拼成 [k0, k0, k1, k1, ...],每 2 个相邻 Q 头共用同一个 K。
- 注意是 `interleave`(交错)不是 `repeat`,这样原来 K0 一定对应到 Q0 和 Q1,而不是 Q0 和 Q8。

为什么不直接用 broadcast?——broadcast 不会改变张量形状,而矩阵乘法需要头数对齐。所以显式复制。

### 3.7 `compute_rope_params`(行 266-347) — 预计算 cos/sin

```python
freq_indices = torch.arange(0, head_dim, 2)       # [0,2,4,...,126] 共 head_dim/2 个
exponents = freq_indices.float() / head_dim
scales = theta_base ** exponents                  # theta_base^(2i/d)
inv_freq = 1.0 / scales                           # 1 / scales,就是 θ_i
positions = torch.arange(context_length)           # [0,1,2,...,40959]
angles = positions.unsqueeze(1) * inv_freq.unsqueeze(0)   # [context_length, head_dim/2]
angles = torch.cat([angles, angles], dim=1)       # 拼成 [context_length, head_dim]
cos = torch.cos(angles); sin = torch.sin(angles)
```

为什么 angles 拼接前后两份相同?因为本实现的 RoPE 配对方式是**前后半对应**:
- 标准相邻配对:`(x0,x1),(x2,x3),...` ← 不用这种
- 本实现的配对:`(x0,x4),(x1,x5),(x2,x6),(x3,x7)` ← 前后半配对,所以 angles 也得复制成前后两半相同,让对应的 cos/sin 一致。

`theta_base = 1_000_000` 的含义:频率基数,越大对应位置感知越细腻,长上下文友好。Qwen3 选 1e6 是为了支持 40K 上下文。

### 3.8 `apply_rope`(行 349-439) — 应用旋转

```python
x1 = x[..., :head_dim//2]   # 前半
x2 = x[..., head_dim//2:]    # 后半
rotated = torch.cat((-x2, x1), dim=-1)   # rotate_half(x) = [-后半, 前半]
cos = cos[offset:offset+seq_len].unsqueeze(0).unsqueeze(0)
sin = sin[offset:offset+seq_len].unsqueeze(0).unsqueeze(0)
x_rotated = x * cos + rotated * sin
```

数学上对应二维旋转:
$$
\begin{bmatrix}x_0' \\ x_4'\end{bmatrix} = \begin{bmatrix}\cos\theta & -\sin\theta \\ \sin\theta & \cos\theta\end{bmatrix}\begin{bmatrix}x_0 \\ x_4\end{bmatrix}
$$

`rotate_half(x) = [-x2, x1]` 实现 `-sin * 第二个分量`。
`offset` 的作用:decode 阶段每次只传 1 个 token,但它的真实位置是 self.current_pos,所以要从 cos 的 offset 处取值,而不是从 0。

### 3.9 `RMSNorm`(行 441-455)

```python
def forward(self, x):
    if self.qwen3_compatible:
        x = x.to(torch.float32)                      # bf16 计算方差会精度不够,转 fp32
    variance = x.pow(2).mean(dim=-1, keepdim=True)
    norm_x = x * torch.rsqrt(variance + self.eps)    # RMSNorm:除均方根
    norm_x = norm_x * self.scale                     # 学习的缩放参数
    return norm_x.to(input_dtype)
```

- RMSNorm = LayerNorm 去掉减均值那一步,**只有缩放,不减均值 → 计算更快,效果几乎一样**。
- `self.scale` 是可学习的 `[ones]`,初始化为 1。
- 强制 fp32 算方差:bf16 算平方易溢出,精度差。

### 3.10 `Qwen3Tokenizer`(行 457-529)

这是个**轻量封装**,直接读 `tokenizer-base.json` (使用 `tokenizers` 库),不依赖 `transformers`:
- `encode`:支持把 `<|im_start|>` 这类特殊 token 单独识别(用正则切),其余走 BPE。
- `_wrap_chat`:手工拼对话模板:
  ```
  <|im_start|>user
  xxx<|im_end|>
  <|im_start|>assistant
  ```
- `eos_token`:Base 版用 `<|endoftext|>`,其它用 `<|im_end|>`(这就是 AGENTS.md 提到的"base vs chat EOS 取决于文件名")。

存在的原因:01 不想依赖整个 `transformers` 框架,自己读 tokenizer.json 才"从零"。

### 3.11 `generate_text`(行 531-588) — 自回归生成

```python
model.reset_kv_cache()
kv_cache = {}
output_logits = model(input_ids, cache=kv_cache)   # 1. prefill 整句 prompt
logits = output_logits[:, -1, :]
probs = torch.softmax(logits, dim=-1)
next_token_id = torch.multinomial(probs, num_samples=1).squeeze(-1)   # 按概率采样

next_input = next_token_id.unsqueeze(-1)
while generated_token < max_len:
    output_logits = model(next_input, kv_cache)    # 2. decode 每次只传 1 个新 token
    logits = output_logits[:, -1, :]
    next_token_id = torch.multinomial(...).squeeze(-1)
    next_input = next_token_id.unsqueeze(-1)
    final_output = torch.cat([final_output, next_input], dim=-1)
```

两阶段:
- prefill:把整 prompt 喂进去算一遍,得到第一个新 token + 所有层的 KV cache。
- decode:每次只把刚生成的 1 个 token 传进去,复用 cache。
- 用 `multinomial` 按概率采样(不是 `argmax` 贪心),输出更有多样性。

### 3.12 `load_qwen3_safetensors_weights`(行 590-636) — 加载 HF 权重

把 HF 张量名映射到自己手写模型的名字:

| HF 名 | 手写模型名 |

| `model.norm.weight` | `final_norm.scale` |
| `model.layers.{i}.input_layernorm.weight` | `trf_blocks.{i}.norm1.scale` |
| `model.layers.{i}.self_attn.q_proj.weight` | `trf_blocks.{i}.att.q_proj.weight` |
| `model.layers.{i}.self_attn.q_norm.weight` | `trf_blocks.{i}.att.q_norm.scale` |

`strict=True`:两边参数必须一一对应,缺一个都报错。这正是你在 AGENTS.md 里看到的"Do not invent alternate key maps"的原因——这个映射是和 HF 权重文件锁死的。

## 4. `02_sft_demo.py` — SFT 监督微调

> **目标**:用对话数据教 Base 模型会聊天,**只对 assistant 回答的部分计算 loss**,prompt 不算。

### 4.1 导入和 `SFTConfig`(行 1-23)

```python
tokenizer = AutoTokenizer.from_pretrained(ModelConfig.REMOTE_MODEL_NAME_BASE)

@dataclass
class SFTConfig:
    train_data_size: int = 10000
    eval_data_size: int = 500
    lr: float = 3e-5           # SFT 典型 lr,比预训练大、比 DPO 大 10 倍
    batch_size: int = 4
    warmup_ratio: float = 0.1
    save_dir: str = "./finetuned/02_sft_demo"
    log_dir: str = "./logs/02_sft_demo"
    eval_iter: int = 100
    log_iter: int = 100
    max_len = 2056             # ⚠ 注意这里没在 dataclass 里,形参写法有点问题:每条数据 token 长度上限
```

`SFTConfig` 是个 dataclass,本质是个简单的"超参数容器",`main()` 可以覆盖默认值。

每个参数含义:
| 参数 | 意义 |
|---|---|
| `lr = 3e-5` | AdamW 学习率,SFT 常见区间 1e-5 ~ 5e-5 |
| `batch_size = 4` | 一次喂 4 条样本 |
| `warmup_ratio = 0.1` | 前 10% 步数线性 warmup,之后余弦衰减 |
| `eval_iter / log_iter` | 每 100 批评估 / 写日志一次 |
| `max_len = 2056` | `apply_chat_template` 截断到这个长度 |

### 4.2 `get_train_data / get_eval_data`(行 26-52)

```python
train_data = load_dataset(ModelConfig.REMOTE_DATASET_NAME)["train_sft"]
train_data = train_data.shuffle().select(range(sft_config.train_data_size))
final_result = []
for i in range(sft_config.train_data_size):
    message_list = train_data[i]["messages"]
    result = tokenizer.apply_chat_template(message_list, tokenize=True,
              truncation=True, max_length=sft_config.max_len)["input_ids"]
    final_result.append(result)

```

- 数据集:`HuggingFaceH4/ultrachat_200k` 的 `train_sft` 子集,每条样本有 `messages` 字段(`[{"role":"user","content":...},{"role":"assistant","content":...}]`)。
- `apply_chat_template` 把对话格式化成 ChatML(`<|im_start|>user\n...<|im_end|>...`)并 tokenize。
- `tokenize=True + truncation=True + max_length` 同时拿到 input_ids 并限制长度。

### 4.3 `create_answer_mask`(行 58-151) — ⭐ SFT 核心之一

Loss 只该算在 assistant 回答部分,这个函数构造一个 `[B, seq]` 的 0/1 mask,只在 assistant 答案 token 上为 1。

**思路**(配合 `_parse_conversation_turns` 和 `_set_answer_masks`):

1. 找到整条样本中所有 `<|im_end|>` 的位置 → `eos_positions`
2. ChatML 里 user 和 assistant 轮次交替出现,所以 **奇数下标是 user,偶数下标是 assistant**(从 0 开始):
   - `user_ends = eos_positions[::2]` 取偶数下标
   - `assistant_ends = eos_positions[1::2]` 取奇数下标
3. 每个 assistant 轮的回答范围:`[user_end + 5, assistant_end + 1]`
   - 这里 `+5` 是跳过 `<|im_end|>` `\n` `<|im_start|>` `assistant` `\n` 这 5 个 token(注释 148 行讲了)
   - `+1` 因为切片是左闭右开,要把 `<|im_end|>` 包括进去

**边界保护**(行 142-151):如果最后一轮被截断,`user_turns` 比 `assistant_turns` 多一个,最后一轮的 assistant 部分就连到结尾(`mask[last_answer_start:] = 1`)。

### 4.4 `compute_loss`(行 154-186) — ⭐ SFT 核心之二

```python
log_probs = torch.log_softmax(logits, dim=-1)            # [B, seq, vocab]
label_token_log_prob = torch.gather(
    input=log_probs,
    dim=-1,
    index=labels.unsqueeze(-1)                          # [B, seq, 1]
).squeeze(-1)                                            # [B, seq]
masked = assistant_mask * (-label_token_log_prob)        # 只保留 assistant 部分
num_active = assistant_mask.sum()
average_loss = masked.sum() / num_active
```

公式上就是标准的 NLL Loss:
$$\mathcal{L} = -\frac{1}{|A|}\sum_{t\in A}\log p(y_t|y_{<t},x),\quad A=\text{assistant 位置集合}$$

代码三步:log_softmax → gather 取出正确 token 的 log prob → 取负乘 mask → 求和除以活跃 token 数。

`num_active == 0`:这一 batch 没找到 assistant 答案(可能截断太短),返回 0 防 NaN。

### 4.5 `cosine_decay`(行 191-208) — 学习率调度

```python
warmup_batch = total_batch * warmup_ratio
if current_batch < warmup_batch:
    return (lr / warmup_batch) * current_batch            # 线性升
else:
    progress = (current_batch - warmup_batch) / (total_batch - warmup_batch)  # 0 → 1
    decay_level = (cos(π*progress) + 1) * 0.5            # 1 → 0
    return lr * decay_level
```

- 前期:线性 warmup,防止初始梯度太大炸。
- 后期:余弦从 1 降到 0,平滑地收到 0。

### 4.6 `eval_model`(行 212-244)

不训练,只算验证集平均 loss:
- `model.eval() + torch.no_grad()`
- 同样的 padding / mask 构造逻辑
- 返回整个评估集 batch loss 的平均

### 4.7 `train`(行 251-345) — 主训练循环

逻辑顺序(行号在代码里有 ✅ 标注对应注释):

1. **行 263-271 初始化**:
   ```python

   model.to(device); model.train()
   optimizer = AdamW(model.parameters(), lr=sft_config.lr)
   ```
   注意:这是 HF 实现,不是 01 里手写的 Qwen3Model。SFT 用现成的更省事。

2. **行 276-277 算批数**:
   ```python
   total_batch = (len(data) + batch_size - 1) // batch_size  # 向上取整
   ```

3. **行 282-305 每个 batch 取数据 + 构造 mask**:
   ```python
   # 按 batch 切 → 找当前 batch 最大长度 → 用 pad_token_id 补齐到等长
   for sample in current_batch_data:
       sample.extend([tokenizer.pad_token_id] * padding_length)
       
   data_tensor = torch.tensor(current_batch_data).to(device)
   input_ids = data_tensor[:, :-1]     # 给模型看的(去掉最后一个)
   labels = data_tensor[:, 1:]        # 要预测的(去掉第一个,左移一位)
   padding_mask = torch.where(labels == pad, 0, 1)
   assistant_mask = create_answer_mask(labels, tokenizer)
   final_mask = assistant_mask & padding_mask
   ```
   ⚠ **注意几个坑**:
   - `sample.extend` 是**原地修改**:数据每轮用一次就污染了,多 epoch 会越 pad 越长。
   - 没给 `model()` 传 `attention_mask`,pad 位置也会参与 attention(语义不对也费显存)。
   - `labels = data_tensor[:, 1:]` 是 next-token 偏移:input 是第 0~n-1,模型要预测第 1~n。

4. **行 308 前向**:
   ```python
   logits = model(input_ids).logits
   loss = compute_loss(logits, labels, final_mask)
   loss.backward()
   optimizer.step(); optimizer.zero_grad()
   ```

5. **行 314-320 学习率调度**:`optimizer.param_groups[0]["lr"] = current_lr` 把当前 lr 写回去。

6. **行 323-339 评估 + 日志**:
   - `should_eval = current_batch % eval_iter == 0`
   - `should_log = ... % log_iter == 0`
   - 写 TensorBoard:`train/loss`、`train/current_lr`、`eval/loss`。

7. **行 343-344 保存**:
   ```python
   model.save_pretrained(save_dir)
   tokenizer.save_pretrained(save_dir)
   ```


## 6. `04_dpo_demo.py` — DPO 偏好优化

> **目标**:在 SFT 之后继续训练,让模型学会"哪个回答更好",对齐人类偏好。

### 6.1 DPO 公式回顾(必记)

$$
\mathcal{L}_{DPO} = -\log\sigma\Big(\beta\cdot\big[\underbrace{(\log\pi_\theta(y_w|x)-\log\pi_\theta(y_l|x))}_{\text{训练模型的偏好差}} - \underbrace{(\log\pi_{ref}(y_w|x)-\log\pi_{ref}(y_l|x))}_{\text{参考模型的偏好差}}\big]\Big)
$$

- $y_w$:偏好(chosen), $y_l$:拒绝(rejected)
- $\pi_\theta$:训练模型, $\pi_{ref}$:参考模型(SFT 快照,冻结)

### 6.2 `DPOConfig`(行 9-23)

```python
@dataclass
class DPOConfig:
    train_data_size: int = 10000
    eval_data_size: int = 500
    lr: float = 3e-6               # ⭐ 比 SFT 小一个量级
    batch_size: int = 4
    warmup_ratio: float = 0.1
    save_dir: str = "./finetuned/03_dpo_demo"
    log_dir: str = "./logs/03_dpo_demo"
    eval_iter: int = 100
    log_iter: int = 100
    beta: float = 0.1              # ⭐ DPO 专属
```

| 参数 | 含义 | 备注 |
|---|---|---|
| `lr=3e-6` | 学习率 | DPO 是精修,步子大了会破坏 SFT 能力 |
| `beta=0.1` | 偏好强度系数 | 小保守大激进,论文推荐 0.1~0.5 |
| `batch_size=4` | 批大小 | DPO 一个 batch 要做 4 次前向(chosen+rejected × 训练模型+参考模型) |

### 6.3 `get_train_data / get_eval_data`(行 26-71)

```python
train_data = load_dataset("./data/ultrafeedback_binarized")["train_prefs"]
for i in range(...):
    message_list = train_data[i]["chosen"]        # 偏好答案(对话)
    result = tokenizer.apply_chat_template(message_list, tokenize=True)["input_ids"]
    chosen_result.append(result)
    # 同样处理 rejected
return chosen_result, rejected_result
```

- 数据集:UltraFeedback 的"二值化"版本,每条样本带 `chosen` 和 `rejected` 两个对话。
- ⚠ 这里**没有 `truncation` 和 `max_length`**,长样本保留全长,显存压力大。

### 6.4 `create_answer_mask / _parse_conversation_turns / _set_answer_masks`(行 77-170)

和 02 SFT 完全相同的逻辑,直接复用。DPO 同样只在 assistant 回答 token 上算 log prob。

### 6.5 `compute_loss`(行 173-187) — ⭐ DPO 核心

```python
def compute_loss(chosen_log_probs, rejected_log_probs,
                  ref_chosen_log_probs, ref_rejected_log_probs, beta):
    margin = chosen_log_probs - rejected_log_probs \
           - (ref_chosen_log_probs - ref_rejected_log_probs)
    loss = - torch.nn.functional.logsigmoid(beta * margin)
    return loss.mean()
```

逐行对应公式:
- `chosen_log_probs - rejected_log_probs` = 训练模型的偏好差
- `ref_chosen_log_probs - ref_rejected_log_probs` = 参考模型的偏好差
- `margin = 两者之差`
- `-logsigmoid(beta * margin)` = $-\log\sigma(\beta\cdot\text{margin})$
- `.mean()` = batch 平均

训练目标:让 `margin > 0`,即训练模型偏好差大于参考模型偏好差,loss → 0。

### 6.6 `compute_log_probs`(行 189-214) — 注意和 SFT 不同

```python
log_probs = torch.log_softmax(logits, dim=-1)
label_token_log_prob = torch.gather(input=log_probs, dim=-1, index=labels.unsqueeze(-1)).squeeze(-1)
masked_label_token_log_prob = assistant_mask * label_token_log_prob
log_probs = masked_label_token_log_prob.sum(dim=-1)   # ⭐ 重要区别
return log_probs
```

对比 SFT 的 `compute_loss`:
- SFT:每 token 的负对数概率 → 求平均 → token 级 loss
- DPO:每 token 的 log_prob → **求和** → 整条回答的对数似然 $\log p(y|x)$

因为 DPO 比的是"整条回答"在两个模型里的概率差,不是单 token 级。

### 6.7 `train`(行 357-528) — 主循环

#### 6.7.1 初始化(行 368-380)

```python

```

- **两个模型从同一个 SFT 快照加载**:DPO 标准做法,参考模型就是 SFT 模型冻结。
- 路径是 `02_sft_demo_backup`(带 `_backup` 的副本),你需要先有这个目录。

#### 6.7.2 每个 batch 的数据 + mask 构造(行 391-439)

对 chosen 和 rejected 各自做:
1. 按 batch 取切片
2. 找 batch 内最大长度 → 用 pad 补齐(同样有原地 extend 污染问题)
3. 切 `input_ids = data_tensor[:, :-1]`, `labels = data_tensor[:, 1:]`
4. 构造 `padding_mask` & `assistant_mask` → 交集 `final_mask`

#### 6.7.3 四次前向传播(行 445-450) — DPO 关键开销

```python

```

为什么 4 次:
- 同一批数据要评估 chosen 和 rejected 两条序列(2×)
- 每条都要走训练模型和参考模型(2×)
- 显存 ≈ SFT × 4,这是 8GB 跑不动的主因。

#### 6.7.4 算 4 个 log_prob + loss(行 453-487)

```python

ref_chosen_log_prob = compute_log_probs(ref_chosen_output_logits, chosen_labels, final_chosen_mask)
ref_rejected_log_prob = compute_log_probs(ref_rejected_output_logits, rejected_labels, final_rejected_mask)

loss = compute_loss(chosen_log_prob, rejected_log_prob,
                    ref_chosen_log_prob, ref_rejected_log_prob,
                    dpo_config.beta)
```

```python

optimizer.step()
optimizer.zero_grad()
current_lr = cosine_decay(...)

```

注意:**`ref_model` 在 `torch.no_grad()` 下做的,不产生梯度**;反向只更新训练模型。

同 SFT,写 TensorBoard + tqdm 进度条 + 保存到 `finetuned/03_dpo_demo`。

## 7. 三阶段流水线一生成总结

把整个仓库的"一生"串起来:

| 阶段 | 文件 | 输入 | 输出 | 学到了什么 |
|---|---|---|---|---|
| 0. 结构成型 | `01_Qwen3.py` | 随机权重 | 能跑但不通顺的模型 | 学会 Qwen3 架构(GQA/RoPE/SwiGLU/KV cache) |
| 1. SFT | `02_sft_demo.py` | Base 模型 + ultrachat 对话数据 | `02_sft_demo` 微调后的模型 | 学会"按 ChatML 模板对话" |
| 2. 验证 | `03_model_generate.py` | 微调后模型 + prompt | 生成的回复 | 确认模型会说话 |
| 3. DPO | `04_dpo_demo.py` | SFT 模型 + UltraFeedback 偏好对 | `03_dpo_demo` 对齐后模型 | 学会"哪个回答更好" |

### 7.1 共用工具

- `llm_config.py`:三个全局路径(模型 Base、模型 Instruct、数据集)。
- `device_utils.py`:`cuda > mps > cpu` 设备选择。
- `create_answer_mask`(在 02/04 共有):基于 `<|im_end|>` 切 user/assistant 轮次,标记需要算 loss 的位置。
- `cosine_decay`(在 02/04 共有):warmup + 余弦衰减的学习率调度。

### 7.2 三个 Loss 函数的对比

| 阶段 | Loss 公式 | 单位 | 输入 |
|---|---|---|---|
| SFT | $-\frac{1}{\|A\|}\sum_{t\in A}\log p(y_t\|y_{<t},x)$ | 单 token | logits + labels + answer_mask |
| DPO | $-\log\sigma\Big(\beta\cdot[(\Delta_{\text{train}})-(\Delta_{\text{ref}})]\Big)$ | 整条回答对数似然之差 | 4 个 log_prob + beta |

**关键差异**:SFT 关注"每一步生成对不对",DPO 关注"整条回答在两个模型里的概率差"。这就是为什么 DPO 的 `compute_log_probs` 用 `sum(dim=-1)` 而 SFT 用 `mean`。

### 7.3 一些代码层面的坑(来自你这两周的实战)

1. **`sample.extend([pad]*n)` 原地修改数据**(02 行 290、04 行 258/282)→ 多 epoch 会越 pad 越长。修复:改成构造副本。
2. **没传 `attention_mask` 给 model()** → pad 位置也参与 attention,语义错且费显存。
3. **`SFTConfig.max_len = 2056`** 在 dataclass 外面单独定义,不在 dataclass 字段里 → 类型不正确,实例会覆盖类属性。
4. **`04_dpo_demo.py:373` 加载路径是 `02_sft_demo_backup`** → 你需要先把 SFT 输出复制一份成 `_backup` 目录。
5. **8GB 显存**:SFT 默认 fp32 全参数必爆,DPO 4 次前向更爆。需用 bf16 + max_length=512 + batch_size=1 才走得通(详情见 `SFT_显存优化与代码改动清单.md`)。
