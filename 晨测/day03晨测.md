## 1、为什么 DPO 需要引入参考模型（ref_model）？

```
DPO 损失函数：

  L_DPO = -log σ(β[ (logπ_θ(y_w|x) - logπ_θ(y_l|x)) - (logπ_ref(y_w|x) - logπ_ref(y_l|x)) ])

引入参考模型的两层考量：

1. 提供稳定基线
   不只是要求模型"更喜欢 chosen"，而是要求"比参考模型更明显地喜欢 chosen"。
   这样既学到了偏好，又尽量保持原有模型的语言能力和输出风格。

2. 防止 reward hacking
   没有 ref_model，模型可以同时降低 chosen 和 rejected 的概率但让 chosen 降得少，
   表面上看差值拉大了，实际是"作弊"。
   ref_model 给了"原始水平"锚点，确保优化是真正的提升。

工程实现：
  - ref_model 全程 torch.no_grad()，不参与梯度计算
  - ref_model 需要设置为评估模式（model.eval()），去掉 Dropout
```

## 2、从训练数据和损失函数两个角度，说明 DPO 和 SFT 的核心区别

```
┌──────────┬─────────────────────────────┬────────────────────────────┐
│          │            SFT              │            DPO            │
├──────────┼─────────────────────────────┼────────────────────────────┤
│ 训练数据  │ (prompt, answer) 一对一      │ (prompt, chosen, rejected) │
│          │ 标准答案，照着学              │ 一对二，学"哪个更好"     │
│          │ 标注成本低                   │ 需要偏好标注，成本高      │
├──────────┼─────────────────────────────┼────────────────────────────┤
│ 损失函数  │ 交叉熵（最大似然估计）        │ 偏好排序损失              │
│          │ L = -Σ log P(y_t|x, y_<t)   │ L = -log σ(β[差值-基线])  │
│          │ 只对 assistant 回答算 loss    │ 拉大 chosen/rejected 差距  │
│          │ 本质：行为克隆               │ 本质：偏好对比学习          │
└──────────┴─────────────────────────────┴────────────────────────────┘

一句话：
  SFT 让模型"背下标准答案"，DPO 让模型"在两个回答中选更优的那个"。
```

## 3、什么时候用 SFT？什么时候用 DPO？

```
┌──────────────────────────────┬──────────────────────────────┐
│         优先用 SFT            │        在 SFT 后用 DPO       │
├──────────────────────────────┼──────────────────────────────┤
│ 有大量高质量（prompt, answer）│ 已有 SFT 过的模型，想进一步优化│
│ 想让模型学特定格式/风格/术语  │ 有偏好标注数据（哪个更好）    │
│ 模型连基本指令遵循都做不好    │ 减少有害/敷衍/不正确输出      │
│ 性价比优先（单模型，训练成本低）│ 在不降基础能力的前提下优化偏好│
└──────────────────────────────┴──────────────────────────────┘

标准流程：

  Base Model → [大量指令数据 SFT] → Instruct Model → [小批量偏好 DPO] → Aligned Model
               学对话格式/领域知识                 微调偏好，提升体验

注意：
  SFT 并非 DPO 的前提，但先做 SFT 会让 DPO 训练更平稳、不易偏离。
  SFT 保障基本能力，DPO 在 SFT 基础上做偏好微调。
```

## 4、LLM 训练过程中，显存占用可以分为哪几个部分

```
以参数 Φ、FP16 混合精度训练为例：

  总显存 ≈ 模型参数 + 梯度 + 优化器状态 + 激活值 + 临时缓冲区

┌───────────┬──────────┬─────────────────────────────────────┐
│ 组成部分   │ 占用大小  │ 说明                               │
├───────────┼──────────┼─────────────────────────────────────┤
│ ① 模型参数 │ 2Φ (FP16)│ 权重矩阵本身                       │
│           │ 4Φ (FP32)│                                    │
├───────────┼──────────┼─────────────────────────────────────┤
│ ② 梯度    │ 2Φ (FP16)│ 反向传播计算的梯度                  │
│           │ 4Φ (FP32)│                                    │
├───────────┼──────────┼─────────────────────────────────────┤
│ ③ 优化器状态│ 8Φ (Adam)│ Adam 存一阶矩(m)+二阶矩(v) 各 4Φ  │
├───────────┼──────────┼─────────────────────────────────────┤
│ ④ 激活值  │ 随 batch  │ 每层中间结果，波动最大的部分         │
│           │ ×seq×hid │ 约 2×batch×seq×hidden_dim           │
├───────────┼──────────┼─────────────────────────────────────┤
│ ⑤ 临时缓冲 │ 额外开销 │ 通信缓冲区、CUDA context 等         │
└───────────┴──────────┴─────────────────────────────────────┘
```

## 5、单卡下训练时，优化显存占用的方式有哪些

```
┌──────────────────┬──────────────────────┬──────────────────┐
│ 优化方式          │ 减少的显存部分        │ 代价              │
├──────────────────┼──────────────────────┼──────────────────┤
│ ① 混合精度(AMP)  │ 参数+梯度 减半        │ 数值溢出风险      │
│ ② 梯度检查点      │ 大幅减少激活值        │ 时间换空间(≈20%) │
│ ③ Offload        │ 优化器/梯度→CPU       │ CPU↔GPU通信开销   │
│ ④ LoRA/QLoRA    │ 只训少量参数(0.1-1%)  │ 模型容量受限      │
│ ⑤ 梯度累积       │ 允许小batch→降激活值  │ 训练步数增多      │
│ ⑥ Flash Attention│ 减少注意力层显存       │ 无精度损失 ✅     │
└──────────────────┴──────────────────────┴──────────────────┘

不同优化技术具体减少哪部分显存：

  混合精度训练         → 模型参数、梯度减半，优化器状态不变
  梯度检查点           → 大幅减少激活值显存（时间换空间）
  ZeRO-Stage 1        → 减少一半优化器状态占用
  ZeRO-Stage 2        → Stage1基础上再减少梯度占用
  ZeRO-Stage 3        → Stage2基础上再减少参数占用
  激活重计算/Offloading → 不用的激活值卸载到CPU
  梯度累积             → 允许更小batch_size，降低激活值显存

单卡实操推荐：

  1B以下  → 全参微调 + AMP
  1B-7B   → LoRA + AMP + Gradient Checkpointing + Flash Attention
  7B-13B  → QLoRA(4bit) + Gradient Checkpointing + 梯度累积（24GB卡）
  13B+    → 单卡基本不可行，需 QLoRA + Offload 组合
```
